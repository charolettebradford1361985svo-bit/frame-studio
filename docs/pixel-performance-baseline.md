# 像素处理 CPU 基线 · 2026-10-22

运行 `node scripts/benchmark-pixels.mjs`。不需要安装额外依赖、素材或服务。

环境：Node v24.6.0，Windows x64。程序生成固定 RGBA：绿色背景、矩形主体、三像素混色边缘和变化的主体 alpha。每批串行处理相同输入 24 次，预热 2 批后测量 7 批。仅变换循环计时，哈希校验在计时之外；输入不变、各批末帧输出一致才输出报告。

## 内存与结论边界

脚本报告最后一批前后的内存差值，单位为字节。此次 RSS / heapUsed / arrayBuffers 分别为：256 色键 `18878464 / -552040 / 18874368`，512 色键 `5988352 / 662464 / 6291456`，整数放大 `31535104 / 11184 / 31457280`。

这些是受 GC 影响的端点差值，**不是峰值、泄漏证据或编辑器内存上限**。脚本只保留批次末帧，不模拟编辑器同时保留所有帧、Canvas、历史和导出缓冲区。

512 色键批次中位耗时约为 256 的 3.47 倍，像素数为 4 倍；单一样本不足以确定内部热点或说明存在异常退化。本批建立基线，不修改算法、不声称提速。没有同质量候选实现与产品延迟目标，因此没有支持优化的对照证据。

此结果不包含图片/视频解码、Canvas、PNG 编码、ZIP、界面响应或可选 AI；不代表浏览器、GPU 或实际用户项目的速度。哈希仅检查重复输出与输入不变，像素正确性仍由相关断言测试验证。测试和构建未与本次基准并行运行；其他系统负载未控制。跨机器时间无需一致。
